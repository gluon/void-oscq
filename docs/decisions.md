# Decisions

One line per decision. Newest entries at the bottom. A dependency not listed in PRD.md section 5, a relaxed performance budget, or a deviation from PRD.md gets an entry here with its reason.

| Date | Decision | Rationale |
| --- | --- | --- |

| 2026-10-09 | GUI: `eframe` / `egui` | Immediate mode, no webview, trivial cross compilation, built in virtualised list primitives (PRD 5, LOCKED) |
| 2026-10-09 | Async runtime: `tokio` multi thread, network layer only | HTTP, WebSocket and timers in one place, UI thread never blocks (PRD 5 and 6.2, LOCKED) |
| 2026-10-09 | HTTP client: `reqwest` with rustls | No OpenSSL on any platform; in reqwest 0.13 the default TLS backend is rustls, `cargo tree -i openssl-sys` finds nothing (PRD 5, LOCKED) |
| 2026-10-09 | WebSocket: `tokio-tungstenite` with rustls (`rustls-tls-webpki-roots`) | Text frames for commands, binary frames for OSC packets (PRD 5, LOCKED) |
| 2026-10-09 | OSC encode and decode: `rosc` | Mature, no unsafe, bundles and common type tags (PRD 5, LOCKED) |
| 2026-10-09 | mDNS and DNS-SD: `mdns-sd` | Pure Rust, identical on three platforms, no Avahi or Bonjour SDK (PRD 5, LOCKED) |
| 2026-10-09 | JSON: `serde` and `serde_json` | Documents deserialised into typed structs, never walked untyped in UI code (PRD 5, LOCKED) |

| 2026-10-09 | Workspace of three crates: `oscq-core`, `oscq-discovery`, `void-oscq`; only `void-oscq` depends on `egui` / `eframe` | Protocol testable without a GUI, reusable by a headless tool (PRD 6.1, LOCKED) |

| 2026-10-09 | `serde_json` feature `unbounded_depth`, with a non recursive depth scan rejecting JSON nested deeper than 160 before parsing | The default limit of 128 is below the 64 node cap (each node nests twice); the scan bounds stack use instead. Parsing at the limit is tested on a 512 KiB stack |
| 2026-10-09 | Nodes deeper than 64 keep an empty `CONTENTS` and get a `DepthLimit` diagnostic | PRD 11 "cap depth at 64 and report": the rest of the tree stays browsable |
| 2026-10-09 | Problems that do not prevent parsing are diagnostics, not errors; the offending raw value is kept in `extra` | PRD 7.1 "render what is there"; the raw body is also kept whole for the JSON tab |
| 2026-10-09 | Missing `FULL_PATH` is derived from the parent path and the child key, with a diagnostic; not reported on `OVERLOADS` entries | The proposal's own `OVERLOADS` example and OSCQuery Helper's sample document carry no `FULL_PATH` |
| 2026-10-09 | A node with both `CONTENTS` and `TYPE` is a container and a method | Not ruled by the human. VVOSCQueryProtocol nodes carry both, and Vidvox oscqueryhtml treats such a node as a control (`test/extract.js`, "has contents and type", commit `ca25041`) |
| 2026-10-09 | OSC addresses validated strictly against OSC 1.0: printable ASCII, none of `space # * , / ? [ ] { }`, no empty part | PRD 11 case "characters legal in JSON but not in OSC"; such nodes are shown and never sent to |
| 2026-10-09 | `TYPE` accepts one leading `,`; array groups nested deeper than 16 are rejected | The wire form of a type tag string starts with `,`; the cap bounds every recursion over a signature |
| 2026-10-09 | Coercion: a non integral number sent to `i` or `h` is rounded to nearest, ties away from zero, then range checked | PRD 7.5 "never send a float where the node declared an int"; the rounding rule is this project's choice |
| 2026-10-09 | `S` (symbol) is refused on send | `rosc` 0.11 has no symbol type; sending it as `s` would change the type tag |
| 2026-10-09 | `OSC_TRANSPORT` compared case insensitively; any other value is a diagnostic and UDP is assumed | The proposal defines `"TCP"` and `"UDP"` only; VVOSCQueryProtocol falls back to UDP |
| 2026-10-09 | `OSC_PORT` present but not a valid port makes the server not controllable, it is not inferred | The ruling infers the port only when the key is absent |
| 2026-10-09 | Ports given as numeric strings are accepted | VVOSCQueryProtocol client does the same (`VVOSCQueryRemoteServer.mm`) |
| 2026-10-09 | An attribute query answered 200 with keys other than the queried one is treated like an empty object | A server that ignores the query must not be reported as broken |
| 2026-10-09 | HTTP client: no proxy, connect timeout 3 s, request timeout 10 s, body cap 64 MB | OSCQuery servers are on the LAN, a system proxy would misroute; the timeouts are this project's choice |
| 2026-10-09 | OSC destination resolution prefers IPv4, falls back to the first address | Matches the discovery preference in PRD 8.2 |
| 2026-10-09 | `CONTENTS` children are kept sorted by name | `serde_json` without `preserve_order` does not keep server order; enabling it would add `indexmap` |
| 2026-10-09 | Dev dependencies of `oscq-core`: `anyhow` for the example, `tokio` features `macros` and `io-util` for the synthetic server | `anyhow` is in PRD 5 for binary boundaries; no new crate |
| 2026-10-09 | `flume` replaces `crossbeam-channel` as the network to UI channel and the `Discovery` receiver, in PRD 5, 6.2 and 8.1 | Human ruling on the M1 conflict: `mdns-sd` returns a `flume::Receiver`, which covers the same need and avoids a bridge thread in M2. Supersedes the `crossbeam-channel` part of the entry above |
| 2026-10-09 | `flume` in both directions: UI to network `flume::Sender<Command>` received with `recv_async`, network to UI `flume::Sender<Event>`; `tokio::sync::mpsc` dropped from PRD 6.2 | Human ruling: one channel crate for the whole project |
| 2026-10-09 | `flume` declared once in `[workspace.dependencies]`, version 0.12 without default features, feature `async`; `oscq-core` uses it with `workspace = true` | Same 0.12 series as `mdns-sd`, so `Discovery` returns the very receiver type `mdns-sd` produces; `async` provides `recv_async`. Other crates add `flume.workspace = true` when they use a channel |
| 2026-10-09 | `ServerId` (process unique counter) and `DiscoveredServer` with its address types live in `oscq-core` | Shared by discovery and the future `Event` vocabulary (PRD 6.3); `oscq-discovery` depends on `oscq-core` |
| 2026-10-09 | `flume` workspace feature `select` added | The discovery worker waits on both browse receivers, the stop signal and the liveness timer with one `flume::Selector` in one thread |
| 2026-10-09 | Deduplication key: service kind, host name lower cased without the trailing dot, port. The instance name is display only | PRD 8.2 "by host and port, not by instance name"; the kind is part of the key because `_osc._udp` and `_oscjson._tcp` on one port are different services |
| 2026-10-09 | Addresses are never discarded. Order: IPv4, IPv6, IPv6 link local, then loopback and the Docker default bridge 172.17.0.0/16 as fallbacks | PRD 8.2 reads "skip loopback and Docker ... keep the others as fallbacks"; read as never preferred but kept, so a server on the same machine with no LAN still works. The rest of 172.16.0.0/12 is ordinary private space and is not demoted. Interpretation to confirm |
| 2026-10-09 | A server's address list is the union of everything seen for it; interfaces are ordered by OS index | `mdns-sd` resolves one interface at a time (observed: loopback first, LAN second); a union keeps the earlier one as a fallback |
| 2026-10-09 | Every `ServiceRemoved` marks the server stale; stale servers are kept, never deleted automatically, and revive with the same `ServerId` | `mdns-sd` 0.21 emits the same event for a goodbye and for cache expiry, so they cannot be told apart; PRD 8.2 "mark stale, let the user retry" |
| 2026-10-09 | Liveness check: `mdns-sd` `verify` on every advertised instance every 15 s, answer timeout 10 s (`VERIFY_TIMEOUT_DEFAULT`, RFC 6762 10.4); on by default on Windows only, configurable elsewhere | PRD 8.2 Windows fallback. Proven by a test that kills a publisher process: stale with the check, still listed without it over the same window |
| 2026-10-09 | Loopback interfaces are browsed (the `mdns-sd` default) | A server on the same machine is found; the real OSCQuery Helper capture showed it on interface 1, the loopback, and on interface 14 |
| 2026-10-09 | `DiscoveryEvent` is `Found`, `Changed`, `Stale`, each with a full server snapshot | PRD 6.3 names `ServerFound` and `ServerLost`; discovery never loses a server, it marks it stale. Mapping to the `Event` vocabulary is left to M3 |
| 2026-10-09 | Manual entries: `host:port` or `[IPv6]:port`, always an OSCQuery server; history of 10, most recent first, case insensitive duplicates removed; persistence left to the application config | PRD 8.2; the config file is PRD 9.7, built in M3 |
| 2026-10-09 | An explicit `ACCESS` always wins; no heuristic overrides it. A `VALUE` present on a write only node is a server inconsistency, not a signal of readability | Human ruling, after the real OSCQuery Helper capture: the Helper declares `ACCESS` 2 on every node by design, `OSCQueryHelper/OSCQueryHelperAppDelegate.m` lines 358 to 360 in VVOSCQueryProtocol commit `cebb6f8`, "access is always write-only in this application (we can't read the remote app's OSC address space)", yet serves `VALUE` on its `T` and `F` nodes |
| 2026-10-09 | PRD 6.3: `Event::ServerLost(ServerId)` replaced by `ServerChanged` and `ServerStale`, each carrying a `DiscoveredServer` whose `stale` flag holds the state | Human ruling after M2: discovery marks stale and never removes, the `Event` vocabulary matches `DiscoveryEvent` (`Found`, `Changed`, `Stale`). Supersedes the mapping left open in the `DiscoveryEvent` entry above |
| 2026-10-09 | The three M2 interpretations are confirmed: loopback and Docker kept as fallbacks, service kind in the deduplication key, Docker demotion limited to 172.17.0.0/16 | Human ruling after M2 acceptance on the LAN: one entry in 0.18 s, lo0 and en0 merged, LAN IPv4 promoted |
| 2026-10-09 | The network half lives in `oscq-core::service`: `Command` in, `Event` out, a notify callback after each event for the UI repaint | No UI dependency, testable headless against the synthetic server, reusable by a future headless tool (PRD 6.1, 6.2) |
| 2026-10-09 | `Command::SendOsc` carries the node's `TypeSignature` and a `refresh_after` flag; `Listen`, `Ignore` wait for M4; discovery runs for the life of the app, so no `StartDiscovery` or `StopDiscovery` command | Coercion needs the declared types; a drag must not refresh 125 times a second; nothing in the UI stops discovery |
| 2026-10-09 | `Event::HostInfo` also carries the resolved OSC destination; `HostInfoUnavailable`, `TreeLoaded` with the raw body, and `ValueChanged` with the `AttributeReply` complete the vocabulary | The UI shows the destination and the advertised or inferred port, the JSON tab shows what arrived, and 204 or `{}` is shown as unavailable |
| 2026-10-09 | Values are fetched on expand as one subtree request per container, the first time it is expanded; on explicit refresh (button, F5) of the selection or the whole tree; after each committed send, as a `?VALUE` query | One request instead of one per child, and the same request loads a subtree the server left out (lazy loading) |
| 2026-10-09 | A send is decided on the value itself: drag sends rate limited to one per 8 ms per path without refresh, the release or commit always sent with a refresh. Text and numeric fields commit on Enter | egui reports `changed()` on every keystroke of a field being edited, and a plain click ends a drag; found by driving the real window, see PITFALLS.md |
| 2026-10-09 | Colour pickers send rate limited, without refresh; their value is refreshed on explicit refresh | The picker gives no release event. The sent value is drawn as unconfirmed meanwhile (PRD 9.6) |
| 2026-10-09 | The widget table of PRD 9.3 is applied literally: `i` without range, `h` with `VALS`, `r` with an `EXTENDED_TYPE`, `ffff` without colour names, and every multi argument type get the raw entry field | The table says anything else gets the raw field. To confirm, notably for `i` without range |
| 2026-10-09 | JSON tab: the exact received text of the selected subtree, sliced with `serde_json` `raw_value`, from the nearest subtree fetched on its own; displayed re-indented, whitespace only; Copy and Save use the exact text | PRD 9.4 "exactly what arrived"; `raw_value` is a feature of a crate in the table |
| 2026-10-09 | Save to file and traffic export write to `<config dir>/exports/<kind>-<unix seconds>.<ext>`, shown in the status line | No file dialog: a dialog crate is not in PRD 5, and PRD 9 allows only two modals |
| 2026-10-09 | The config is read once in `main` before the UI loop; every write, config or export, runs on the runtime through `spawn_blocking`, the config with write then rename; the config directory is computed from the OS conventions without a crate | PRD 6.2 no I/O on the UI thread; PRD 9.7 atomic; no new dependency |
| 2026-10-09 | The last selected server is restored at start when it is a manual entry, when discovery finds it otherwise, and connected | PRD 9.7 |
| 2026-10-09 | Pinned paths are kept in the config and round tripped, with no UI | PRD 17 question 2 is open |
| 2026-10-09 | Traffic tab: outgoing messages only until the WebSocket of M4; Pause freezes the view while recording continues | Nothing is received over UDP by a client |
| 2026-10-09 | The last value sent stays shown, drawn as unconfirmed, until a value read from the server replaces it: a value reply, or a reloaded document carrying a `VALUE` on a readable node. An answer without value (204, `{}`) leaves it. On a node that cannot be read nothing replaces it, and a committed send is not followed by a refresh. Supersedes the refresh after every committed send above | Ruled by the human after the Mac test against OSCQuery Helper: every node is ACCESS 2 and answers `?VALUE` with `{}`, the refresh cleared the sent value and the widget jumped back (PRD 9.6) |
| 2026-10-09 | `i` and `h` without MIN and MAX get an integer drag value bounded by the type, 32 bit for `i`, 64 bit for `h`, coerced to the declared type on send; `i` with `VALS` stays a dropdown. Supersedes the literal reading of the PRD 9.3 table for these two types | Ruled by the human |
| 2026-10-09 | A `HOST_INFO` reply carrying `FULL_PATH` is the server's address space, not a `HOST_INFO`: `query_ignored` is set, a `HostInfoIgnored` diagnostic is returned, no key is read from it, and every default applies. The status bar says so | Max 9 answers `/?HOST_INFO` with its tree (fixtures `max-*.json`). `FULL_PATH` is required on every node and is never a `HOST_INFO` key. Rulings 6 and 8 hold: OSC port inferred from the HTTP port, no error |
| 2026-10-09 | WebSocket: one connection per server, to `WS_IP` and `WS_PORT` or the HTTP address. When neither was given, the single attempt on the HTTP address fails silently: refresh only, no event. Once a session has been live, or when the address was advertised, every failure or drop is retried | PRD 7.4. A server that advertised nothing gets one try; one that advertised, or was live, is expected back |
| 2026-10-09 | Reconnection delay: 500 ms doubled per failure, capped at 15 s, minus up to a fifth at random; reset when a session opens. The random part comes from `std`'s `RandomState`, no random number crate | PRD 7.4 "starting at 500 ms, capped at 15 s, with jitter": jitter below the bound keeps both numbers as upper bounds. First delays in (400, 500] ms and (800, 1000] ms, tested |
| 2026-10-09 | WebSocket connect timeout 3 s, messages and frames capped at 4 MiB | Same timeout as HTTP; a text command carries one path and a binary frame one OSC packet |
| 2026-10-09 | The service owns the wanted listen set of each connection, kept across reconnections; `Command::Listen` and `Command::Ignore` change it and wake the session, which sends only the difference with what this socket was told. A new socket starts from nothing and sends every listen again | PRD 7.4 "re-issue every active LISTEN after a reconnect"; a set difference cannot send a duplicate or miss one |
| 2026-10-09 | `LISTEN` for every method on a tree row drawn in this frame, plus the pinned paths of `config.json` that exist as methods; none for containers; `IGNORE` when a method leaves. Another tab draws no rows, so only pinned methods stay listened to. `ACCESS` is not consulted | PRD 7.4 read literally: "one LISTEN per visible or pinned method". Pinned paths have no UI yet (PRD 17 question 2), only the config field |
| 2026-10-09 | After a reconnection, not after the first connection, the whole tree is reloaded once | Structure changes and values pushed while the socket was down are lost; the proposal makes the client responsible for re-establishing state |
| 2026-10-09 | `PATH_CHANGED` reloads the subtree at its path. `PATH_ADDED` reloads the parent. `PATH_REMOVED` drops the listens at and below the path on both sides, drops local state there, reloads the parent. `PATH_RENAMED` moves listens on both sides, and pending values, expansion, unavailable marks and the selection, then reloads the parents of `OLD` and `NEW` | PRD 7.4 and protocol notes section 7. The reload gives the exact structure and the bodies the JSON tab shows, which a local rename of the model could not |
| 2026-10-09 | Binary frames: one OSC packet each, bundles flattened in order, nesting of bundles and of `[` groups checked without recursion and refused beyond 16 before `rosc` decodes. Each message becomes `ValueChanged` with the values as a `VALUE` array in the proposal's JSON encoding, and a traffic record `in`. A frame that cannot be decoded is dropped with a log warning; the session continues | `rosc` decodes bundles by recursion (PITFALLS.md). Reusing `ValueChanged` and `AttributeReply::Value` sends pushed values through the same state path as values read over HTTP, including replacing an unconfirmed sent value |
| 2026-10-09 | `TransportState` gains `WebSocketLive` and `WebSocketLost { retry_in, reason }`; `Event` gains `PathAdded`, `PathRemoved`, `PathRenamed`; `Command` gains `Listen` and `Ignore`, paths as strings like the other commands | PRD 6.3 vocabulary, extended deliberately |
| 2026-10-09 | Pushed values find their node through a path index rebuilt on each structural change | A tree walk per value would cost thousands of node visits per update on a 5000 node tree |
| 2026-10-09 | `futures-util` 0.3 is a direct dependency of `oscq-core`, features `sink` and `std`; `tokio` gains the `macros` feature there | Its `StreamExt` and `SinkExt` drive the `tokio-tungstenite` stream; the crate was already in the graph through `tokio-tungstenite`, same version, `Cargo.lock` gains no package |
| 2026-10-09 | The synthetic server of `oscq-core/tests/common` gains a WebSocket on its HTTP port. It is shared by path with the `synthetic_server` example and the `void-oscq` tests, which take `futures-util`, `tokio-tungstenite` and `tokio` features as dev dependencies only | One server for every test and measurement, no fourth crate (PRD 6.1 has three) |
| 2026-10-09 | Budgets are `#[ignore]` tests named `budget_`, asserting the PRD 10 numbers on a release build and refusing to run on a debug one. The in process ones run in CI on three OS in a `budgets` job; the real binary one needs a display and is run by hand. The release binary size is printed in CI, not gated | PRD 10 "M4 verifies them with a committed benchmark"; PRD 10 defers the binary size remedy, glow, to M5 |
| 2026-10-09 | Sending OSC over the WebSocket, opt in per server (PRD 7.5), is not built in M4 | M4 covers listening and incoming binary frames; sends stay on UDP. Backlog |

## PRD 10 budgets, measured

Measured on 2026-10-09 on commit `d664f1d`, release build, against the synthetic server's document of 5000 methods in 50 containers. Container: Linux x86_64, 4 cores, Xvfb with Mesa software rendering (lavapipe, llvmpipe), no GPU. These are measurements against a synthetic server in a container, not on the human's Mac and not against real software. In process tests: `cargo test --release --workspace -- --ignored budget_ --skip budget_real_binary --nocapture --test-threads=1`. Real binary: `cargo test --release -p void-oscq --test budgets_binary -- --ignored --nocapture` with `DISPLAY` set.

The 4342 ms launch was not reproduced: not with the Mesa shader cache emptied (138.0 ms), not on a fresh X display (96.0 ms). Its cause is not found.
